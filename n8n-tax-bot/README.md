# Налоговый бот ИП «МК» (n8n + Telegram + Google Таблица)

Бот принимает в Telegram фото чеков и PDF-выписки Kaspi. Он вносит их в Google-таблицу
[«Налоги ИП МК»](https://docs.google.com/spreadsheets/d/1epYsyQoB1FgexKBqlWgGdriKxeO86hXDe0_VYL9EzdY/edit)
и отвечает суммой налога и датами, с которых нужны следующие выписка и чеки.

## Как пользоваться

| Что отправить | Что сделает бот |
|---|---|
| Фото чека или накладной (можно несколько сразу) | Распознает дату, продавца, сумму и ФП, проверит на дубли, добавит в лист «Расходы». Ответит, что добавил, и пришлёт текущий налог. |
| PDF-выписку Kaspi | Возьмёт поступления с начала периода, уберёт переводы своих денег (КНП 342), возвраты и дубли, сверит с итоговой строкой «Итого обороты» и добавит в лист «Доходы». Пришлёт два сообщения: что принято и полный расчёт с датами, с которых нужны следующие выписка и чеки. |
| `/итог` или любой текст | Полный расчёт. |
| `/start` | Короткая инструкция. |

Если сверка выписки не сошлась, бот ничего не записывает и просит прислать PDF ещё раз.
Excel-выписки бот не принимает: в них нет итоговой строки, по которой можно проверить распознавание.

## Как считается налог

Всё считают формулы на листе «Итог». Синие ячейки можно менять:

- **Начало периода** (сейчас 01.10.2026). Доходы и чеки до этой даты в расчёт не входят.
- **Ставка ИПН** (10%).
- **Ранее начислено по уведомлению** (146 000 ₸).

Налог = (доходы − расходы по чекам) × ставка + ранее начислено.
Названия строк в столбце A листа «Итог» читает бот, поэтому переименовывать их нельзя.

## Установка (один раз, около 20 минут)

1. **Бот в Telegram.** Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, задайте имя и сохраните токен.
2. **n8n.** Подойдёт n8n Cloud или свой сервер с HTTPS: Telegram отправляет сообщения на публичный адрес.
3. **Доступы в n8n** (Credentials → Add credential):
   - *Telegram API*: токен из шага 1;
   - *OpenAI*: ключ API с platform.openai.com;
   - *Google Sheets OAuth2 API*: вход под Google-аккаунтом, которому принадлежит таблица.
4. **Импорт.** Workflows → Import from File → `workflow.json`.
5. **Подключите доступы к узлам.** Откройте узлы с красным значком и выберите доступ:
   - Telegram: «Telegram», «Скачать фото», «Скачать PDF», «Ответ», «Нет доступа»;
   - OpenAI: «OpenAI: чек», «OpenAI: выписка»;
   - Google Sheets: «Расходы: прочитать», «Расходы: добавить», «Доходы: прочитать», «Доходы: добавить», «Выписки: записать», «Итог: прочитать».
6. **Включите сценарий** переключателем Active.
7. **Закройте бота от чужих.** Напишите боту что угодно, и он пришлёт ваш chat id. Впишите его в узел «Разбор сообщения»:
   `const ALLOWED_CHAT_IDS = ['123456789'];`, затем сохраните. Пока список пуст, бот отвечает всем только их chat id.
8. Отправьте `/итог`. Бот должен прислать текущий расчёт.

## Что проверять самому

- Распознавание чеков проверено на реальных чеках (Gazoil, PetroRetail, VARUS, Траст-Караганда, повёрнутая накладная Imex): суммы, даты и ФП совпали. Плохое фото модель всё равно может прочитать неверно, поэтому строки с пометкой «бот» в листе «Расходы» стоит просматривать раз в неделю.
- По чекам без вашего ИИН (колонка «ИИН покупателя в чеке» = «нет») у налоговой могут быть вопросы. Просите кассира пробивать чек на ИИН 870727350990.
- Если в назначении платежа клиента указан НДС, а вы не плательщик НДС, это нужно исправить в счетах.

## Для разработки

- Код узлов лежит в `src/`, сценарий собирается командой `python3 build.py` в `workflow.json`.
- `node test/run.mjs` прогоняет код узлов на тестовых данных без сети.
- `node test/live_check.mjs фото.jpg` и `node test/live_statement.mjs` проверяют промпты на живом OpenAI (нужен `OPENAI_API_KEY`).
- Модель задаётся в узле «Разбор сообщения» (`MODEL`, сейчас `gpt-5.5`).

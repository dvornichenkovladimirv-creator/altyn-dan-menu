# Бюджет: структура и план разработки

Статус: черновик плана. Прототип (v0) в `docs/` — кликабельный макет, чтобы проверить структуру на реальном телефоне. Окончательные решения — в разделе 2.

## 1. Цель

Одно приложение на телефоне, где за 10 секунд записываешь трату и в любой момент видишь:
- сколько можно тратить сегодня, чтобы хватило на обязательные платежи;
- сколько останется в конце месяца;
- что будет с деньгами через 3–6 месяцев при текущих привычках.

Критерий успеха: пользуюсь каждый день 2 месяца подряд, прогноз конца месяца ошибается не больше чем на 10%.

## 2. Решения, которые нужно принять до разработки

| # | Вопрос | Варианты | Рекомендация |
|---|--------|----------|--------------|
| 1 | Кто пользуется | один / семья (общий бюджет) | зависит от ответа — меняет модель данных и хранение |
| 2 | Где данные | только телефон / облако (Supabase) | облако: телефон теряется, данные — нет |
| 3 | Как вносить траты | вручную / импорт выписки банка / оба | вручную + импорт выписки позже (этап 3) |
| 4 | Счета | один общий баланс / несколько (карта, наличные, депозит) | несколько счетов, но без мультивалютности на старте |
| 5 | Платформа | веб-приложение (PWA) / нативное (App Store, Google Play) | PWA: бесплатно, без магазинов, iOS и Android, офлайн |

## 3. Структура данных

```
Пользователь
 └─ Бюджет (личный или общий)
     ├─ Счета            — название, тип (карта/наличные/депозит), начальный остаток
     ├─ Категории         — название, тип (доход/расход), группа, лимит в месяц
     ├─ Постоянные        — шаблон: тип, название, сумма, категория, счёт,
     │                      периодичность (месяц/неделя/год), день, с/по даты
     ├─ Операции          — дата, сумма, тип (доход/расход/перевод), категория,
     │                      счёт, комментарий, ссылка на постоянный (если из шаблона)
     ├─ Цели накоплений   — название, сумма, срок, сколько отложено
     └─ Настройки         — валюта, неснижаемый остаток, начало месяца (день зарплаты)
```

Ключевые правила:
- **Постоянный** — это шаблон (план). **Операция** — факт. Отметка «оплачено» создаёт операцию из шаблона; сумма может отличаться от плана (коммуналка).
- **Переменные** траты — все операции без ссылки на шаблон.
- **Перевод** между счетами не считается ни доходом, ни расходом.
- Сумма постоянного может меняться: хранить историю изменений, чтобы прошлые месяцы не пересчитывались.

## 4. Структура экранов

```
Нижнее меню
├─ Обзор         баланс · «можно тратить в день» · остаток на конец месяца ·
│                траты по категориям vs лимиты · ближайшие платежи
├─ Операции      список по дням · фильтр доход/расход/счёт/категория · поиск
├─ Постоянные    план месяца с галочками «оплачено» · просроченные · шаблоны
├─ Прогноз       этот месяц · 6 месяцев (график + таблица) · «что если»
└─ Ещё           счета · категории и лимиты · цели · импорт/экспорт · настройки
Кнопка «+»       быстрый ввод: сумма → категория → готово (≤ 3 касаний)
```

## 5. Логика прогноза

1. **Остаток на конец месяца** = баланс сейчас + неполученные постоянные доходы − неоплаченные постоянные расходы − ожидаемые переменные траты до конца месяца.
2. **Ожидаемые переменные траты** = среднее в день за последние 3 месяца, смешанное с темпом текущего месяца. Без истории — только темп текущего месяца.
3. **Можно тратить в день** = (баланс + ожидаемые доходы − обязательные платежи − подушка) / оставшиеся дни.
4. **6 месяцев вперёд**: постоянные по шаблонам (с учётом дат окончания кредитов) + переменные по среднему. Предупреждение, если баланс уходит в минус.
5. **«Что если»** (этап 2): «если сокращу кафе на 20%», «если возьму кредит 30 000/мес» — и сразу видно, как меняется прогноз.

## 6. Этапы

| Этап | Что входит | Результат | Срок* |
|------|-----------|-----------|-------|
| 0. Прототип ✅ | экраны, постоянные/переменные, прогноз, локальное хранение | можно потрогать на телефоне | готово |
| 1. MVP | счета и переводы, день начала месяца = день зарплаты, сумма факта ≠ плана, быстрый ввод, публикация | ежедневное использование | 1–2 дня |
| 2. Облако | Supabase: вход, синхронизация, общий бюджет (если нужен), «что если», цели | данные не теряются, работает на 2+ устройствах | 2–3 дня |
| 3. Автоматизация | импорт выписки банка (CSV/PDF), автокатегории по прошлым операциям | ручной ввод почти не нужен | 2–3 дня |
| 4. Уведомления | напоминание о платежах, превышение лимита, итоги месяца (Telegram/почта) | приложение само подсказывает | 1–2 дня |

\* время работы, не календарное; после каждого этапа — проверка на телефоне и ваше «ок».

## 7. Риски

- **Забрасывание ввода** — главный риск любого бюджета. Ответ: быстрый ввод, импорт выписки, ежедневное напоминание.
- **Потеря данных** при локальном хранении — снимается этапом 2.
- **Неточный прогноз в первый месяц** — честно показывать «мало данных».
